## Reusable UI and state assessment

Vue components are globally registered, with thin page containers wrapping large components. `C_Map.vue` (1,122 lines), `C_Add.vue` (630), `C_Edit.vue` (631), and `C_Settings.vue` (534) duplicate map setup, access tokens, pulsing-marker code, API calls, and styling. There is no Vuex/Pinia store; for this application's size that is not itself a defect. V2 should use small composables for shared map/data behavior and keep server state in Supabase queries rather than add a global store by default.

Element UI provides consistent forms/tables, but Vue 2 and Element UI are legacy. V2 should use accessible native controls plus a small Vue 3 component set only where it saves real code. Do not recreate every v1 screen before the core research flow works.
